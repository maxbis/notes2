# Zo was het vroeger... en hoe het vandaag is geworden

Decennialang draaide programmeren vooral om het leren van een taal.

Een ontwikkelaar begon met een idee:

> "Ik wil een knop die data opslaat."

Daarna werd dat idee vertaald naar syntax:

`if user.clicked(): save_data()`

Succes hing af van het kennen van de juiste trefwoorden, interpunctie en regels van de programmeertaal. De uitdaging was om ideeen om te zetten in code.

## En hoe het vandaag is geworden...

Vandaag verandert AI die relatie.

De uitdaging is niet langer in de eerste plaats:

**Ideeen -> Syntax**

maar steeds meer:

**Ideeen -> Duidelijkheid**

Het vermogen om intentie helder uit te drukken wordt een van de waardevolste vaardigheden in softwareontwikkeling.

Een AI kan vaak de syntax genereren, maar kan niet betrouwbaar de intentie genereren. Die komt nog steeds van de ontwikkelaar.

De moderne ontwikkelaar moet vragen kunnen beantwoorden zoals:

- Wat is het probleem dat we oplossen?
- Hoe ziet succes eruit?
- Wat moet er gebeuren in normale situaties?
- Wat moet er gebeuren als er iets misgaat?
- Welke beperkingen zijn er?
- Welke voorbeelden maken het gewenste gedrag duidelijk?
- Hoe testen we of de oplossing correct is?
- Komt het resultaat werkelijk overeen met de oorspronkelijke bedoeling?

In plaats van elke regel code handmatig te schrijven, treden ontwikkelaars steeds vaker op als architect, ontwerper, reviewer en communicator.

Een vage instructie levert vage software op.

Een heldere intentie levert heldere software op.

## Bijvoorbeeld

**Oude denkwijze**

> "Hoe schrijf ik deze loop in Python?"

**Nieuwe denkwijze**

> "Ik heb een systeem nodig dat inzendingen van studenten verwerkt, duplicaten afwijst, duidelijke feedback geeft en bruikbaar blijft voor docenten met weinig technische kennis."

De AI kan helpen om de loop te maken. De ontwikkelaar moet de uitkomst definieren.

Dit betekent dat vaardigheden die traditioneel als "soft skills" werden gezien, technische vaardigheden aan het worden zijn:

- Helder communiceren
- Requirements definieren
- Voorbeelden geven
- Randgevallen identificeren
- Resultaten beoordelen
- Instructies verfijnen
- Intentie verwoorden

## Nieuwe programmeertaal

De programmeertaal van de toekomst is niet Python, JavaScript, Java of C#.

De programmeertaal van de toekomst is duidelijkheid.

Wie helder kan beschrijven wat hij wil, waarom hij het wil, hoe goed eruitziet en hoe succes wordt gemeten, zal steeds complexere systemen kunnen bouwen, zelfs zonder zelf elke regel code te schrijven.

De syntax wordt steeds meer geautomatiseerd.

Het denken niet.
